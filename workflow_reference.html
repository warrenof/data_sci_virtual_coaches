02 CV Design — Validate Setup Before Any Model Runs GATE ▶
✓
? Duplicate rows in data?
YES GroupKFold on full-feature-vector hash. Keeps duplicates in same fold — prevents leakage.
NO Standard KFold or StratifiedKFold depending on target balance.
? Dominant categorical feature (from Phase 1)?
YES Upgrade to StratifiedGroupKFold — stratify on dominant category, group on hash. Both problems solved simultaneously.
NO GroupKFold or KFold is sufficient.

Fold sanity checks — run before fitting any model

  • Plot target distribution per fold — mean, std, min, max
  • Plot dominant feature category counts per fold
  • Plot outlier distribution per fold — extreme y values concentrated in one fold?
  • Fit null model per fold (predict fold mean) — verify R² ≈ 0 across all folds
⛔ STOP — CV setup is broken if:
Any fold mean deviates > 2× the inter-fold std from the grand mean, OR null R² is non-uniform across folds. Redesign fold strategy before proceeding. Do not trust any scores from a broken CV.
Rule of thumb The fold composition check takes 10 minutes. The alternative is discovering your CV is broken after submitting to a leaderboard.

03 Baseline — Establish the Signal Floor BUILD ▶
✓
  • Fit simplest possible model — dominant feature only, default params, no tuning
  • Record OOF R² and per-fold scores. This number is your signal floor.
  • Add top-N features by mutual info one at a time — measure delta R² per addition
  • Stop adding when marginal gain < 0.005 R²
? OOF std across folds > 0.05?
YES High variance — suspect CV setup or outlier placement issue. Return to Phase 2 before proceeding.
NO CV is stable. Record the feature count at which gains plateau — this constrains Phase 10.
Rule of thumb The baseline model tells you what fraction of variance is recoverable without any engineering. If baseline is already within 0.05 of the theoretical ceiling, complexity has almost nowhere to go.

04 Encoding Strategy — The Highest-Leverage Decision CHECK ▶
✓

Test in parallel — same CV, same model

? Tree-based model?
YES Test three encodings: Ordinal · Smoothed Target Encoding (alpha 10–20) · OHE. Compare OOF R² per encoding, inspect per-fold — don't just compare means.
NO Linear → OHE only. Neural → embeddings for high-cardinality, OHE for low.
? Ordinal beats Target Encoding on dominant feature?
YES Model is reconstructing group structure from binary proxies via repeated splits. Check feature importance — a binary feature at >30% importance is the tell. Ordinal encoding may be the ceiling for this model family.
NO TE is working. Tune smoothing parameter. TE collapses category to group mean — verify that sub-group structure isn't lost (check residuals within category groups).
⚠ TE leakage risk
Target encoding must be fit inside each CV fold — never on the full training set. Fitting on full data leaks target information into validation folds and inflates OOF by 0.01–0.03.

07 Hyperparameter Tuning — Avoid Pathological Regions PITFALL ▶
✓

Sequence matters

  • Coarse grid first — 20–50 trials, wide ranges, log scale for learning rate
  • Plot learning curves for top configs — do trees converge before n_estimators limit?
  • Fine search only after coarse confirms sensible parameter region
? Learning rate < 0.02 appearing in top configs?
YES Convergence trap — model needs far more trees than budget allows. Add lr ≥ 0.02 floor, or scale n_estimators proportionally. Random search treats lr and n_estimators as independent; they are coupled.
NO Safe to proceed to fine search. Use Bayesian TPE or CMA-ES — both model parameter interactions that random search misses.
? Fine search gain > 0.003 R² over coarse?
YES Adopt fine-tuned params.
NO Coarse grid was sufficient. Don't over-invest in search — the returns are in the ensemble.
⚠ Random search failure mode
Random search is pathologically bad at learning dependencies between coupled parameters. If you must use it, constrain the search space with domain knowledge floors/ceilings before running. Bayesian TPE is almost always worth it for >5 parameters.

08 Ensemble — Diversity Audit Before Blending CHECK ▶
✓
⚠ Use OOF residual correlation — not prediction correlation
Models can have near-identical predictions but different error patterns. Residual correlation is what determines whether blending adds value.
? Any pair OOF residual correlation > 0.90?
YES Models are redundant — one adds no diversity. Blending them will not improve generalisation. Find a model with genuinely different inductive bias.
NO Blending is worthwhile. Start with equal weights, then grid search.
  • Grid search blend weights — minimise OOF MSE directly
  • Note: optimal weights rarely match individual accuracy rankings
  • Check: does weakest model improve OOF when added?
? Weakest model OOF residual r < 0.70 with ensemble?
YES Include — even if individually weaker. Diverse errors improve stability on held-out data.
NO Exclude — redundant, not diverse. Adding it dilutes signal.
What "genuinely different" means Different library (LGB vs sklearn GBM) is not genuinely different if they use identical encodings. Genuinely different = different inductive bias: hierarchical / Bayesian / linear / rule-based.

09 Blend Saturation Diagnosis CHECK ▶
✓

Run this before investing in base model improvements

  • Improve one base model in isolation — record its individual OOF delta
  • Recompute full blend OOF with the improved model
  • Compare: how much of the individual gain propagated to the blend?
? Blend gain < 20% of individual model gain?
YES Blend is saturated. Other models already cover this model's signal. Stop optimising that base model — seek structural diversity instead, or accept the current ceiling.
NO Blend not saturated. Continue optimising base models — gains are propagating.
Why this happens Saturation occurs because ensemble members have already covered the signal dimension you just improved. The blend only benefits from signals none of the other members cover.

10 Feature Engineering — Signal Hunting With Budget Awareness BUILD ▶
✓
Compute FE budget before searching At n training rows, dataset reliably supports ~n/10 to n/20 learnable parameters before regularisation is doing all the work. At n=4,209 that's ~200–400 effective parameters — roughly 50–100 interaction features.

Search residuals, not raw y

  • Compute within-dominant-group residuals from best current model
  • Correlate binary features with residuals — not with raw y
  • Most binary-y correlations are mediated by dominant feature — this removes that confound
? Residual correlations > 0.15 exist?
YES Genuine FE candidates. Test within-group, add one at a time, measure OOF delta per feature.
NO Binary features don't add beyond what model finds natively. Move on.
⛔ Stop adding features when OOF gain per feature < 0.001
You're fitting noise. The model will memorise the feature's correlation with this particular train split — it won't generalise.

11 Post-Processing — High Risk, Handle With Care PITFALL ▶
✓
? Matched training rows in test set?
NO No post-processing needed here.
YES Check group size for matched rows.
? Training group size for matched rows ≥ 30?
YES Group mean may beat model prediction. Test on internal holdout before applying.
NO Do not replace model predictions. Group mean variance >> model variance at n < 30.
Bias-variance framing Model prediction: low variance (trained on full data), some bias. Group mean at n=2–4: zero bias, enormous variance. Group mean only wins when n ≥ ~30 and within-group variance is genuinely low.
? Considering pseudo-labeling?
YES Only if model accuracy > 0.90 AND there is clear, measurable distribution shift between train and unlabelled data. Otherwise OOF gain will be inflated — held-out performance will drop.
NO Skip. The risk of OOF inflation is high and real-world generalisation degradation is the typical outcome.
⛔ Pseudo-labeling failure mode
Pseudo-labeled rows share feature manifold with held-out train folds. The model sees deployment-like patterns during retraining — OOF improves artificially. Evaluation on a truly held-out set reveals the truth.

12 Train / Evaluation Gap Diagnosis CHECK ▶
✓
  • Measure: OOF score → held-out test set score. Some degradation is expected (typically 0.005–0.015 R²) — the question is whether it is larger than expected.
  • If the gap is larger than expected, investigate distribution shift before any further optimisation.
  • If no held-out test set exists yet, treat OOF as the primary evaluation signal and be conservative about claims of generalisation.
? Dominant feature has unseen categories in evaluation data?
YES Target encoding falls back to global mean for unseen categories — check how many rows are affected. If <1% of evaluation rows, unseen categories are not the primary driver — look elsewhere.
NO Run Maximum Mean Discrepancy test across feature subspaces to identify which features drift between train and evaluation data.

Diagnosing shift without evaluation labels

  • Compare feature prevalence (binary) and category frequency distributions between train and deployment/evaluation data
  • Train a binary classifier: can it predict whether a row is from train or deployment data? AUC > 0.6 = measurable shift present
  • Inspect which features the classifier uses most — those are the shifted dimensions
  • Check whether shift is in the feature marginals or in the feature–target relationship (concept drift)
Adversarial validation Training a classifier to distinguish train vs. deployment rows is the most practical tool for diagnosing distribution shift without evaluation labels. Combine with MMD for a statistically grounded picture. If AUC is near 0.5, distributions are similar and shift is unlikely to explain the gap.
OOF as the primary signal In production settings without a held-out leaderboard, OOF score is your best available proxy for generalisation. Make it trustworthy (see Phase 2) and treat it as the decision-making metric. Track OOF score across every experiment — it is your lab notebook.

13 Final Model Selection — Choosing What to Ship PITFALL ▶
✓
  • Build OOF residual correlation table across all candidate models
  • Select the blend that minimises OOF MSE — not the model with the highest score on any single evaluation sample
  • Treat any single evaluation score as a noisy estimate — ±0.003 R² variance is normal at typical holdout set sizes. Never optimise against it directly.
  • If a held-out test set exists, reserve it for a single final evaluation — don't use it to iterate
? Does the best-scoring model on your evaluation set have high OOF residual correlation with other ensemble members?
YES It may be overfitting the evaluation sample's particular distribution — a risk any time evaluation data is small or non-representative. Prefer the diversity-optimised blend over the evaluation-optimised one for deployment.
NO The top-scoring model is genuinely stronger. High weight in the blend is justified.
? Is deployment data likely to differ from training data over time?
YES Prefer models with lower variance over those with marginally better point estimates. Diversity-weighted ensembles, models with ordered TE (CatBoost), and regularised linear stacking all tend to degrade more gracefully under distribution drift.
NO Optimise for OOF MSE directly. The evaluation and deployment distributions are exchangeable.
The two-candidate rule Always select two final candidates: the OOF-optimal blend and the simplest model within 0.005 of it. The simpler model is easier to maintain, explain, monitor, and retrain. If the gap is small, default to the simpler one unless you have a strong reason not to.
Avoiding evaluation overfitting Every time you look at a held-out evaluation score and make a modelling decision based on it, you're implicitly fitting to that score. Keep a strict count of how many times you've used it. More than 5–10 looks at the same holdout set makes it a de facto part of training.

14 Ceiling Analysis — Know When to Stop GATE ▶
✓
? Gap between best OOF and theoretical ceiling < 0.05?
YES You're in noise-floor territory. Remaining gap is irreducible measurement noise. Stop optimising — ship it.
NO Real headroom exists. Estimate how much is irreducible vs closable.

Estimating irreducible vs closable gap

  • Fit best model to non-duplicate rows only — compare RMSE to full-data model
  • Plot residual distribution: is variance uniform or does it scale with group mean?
  • Inspect within-group residuals for non-duplicate rows — if large, noise is distributed across full dataset
? Residual variance scales with group mean (heteroscedasticity)?
YES Group-specific transformations or WLS may help. The gap has structure — it's partially closable.
NO Noise is uniform — gap is closable with better feature engineering or model architecture.
The simplest model test Before concluding you need more complexity, ask: does the simplest model that correctly handles the dominant feature already represent the performance ceiling? If a plain GBM with ordinal encoding and log(y) is within 0.005 of your best ensemble, complexity was never the constraint.
